# Библиотека blablablarden

Личная электронная библиотека по философии, истории и математике (плюс
пара разделов вне основной темы — программирование и языки, по отдельной
просьбе). Каталог — дерево разделов произвольной глубины, у каждой книги
есть карточка с онлайн-читалкой, обсуждением и историей правок.

## Возможности

- **Дерево категорий без ограничения глубины** — раздел может содержать
  подразделы, а те — свои подразделы (например, «Математика → Топология →
  Узлы»). Добавляются и удаляются из `/admin`.
- **Поиск на русском и английском** — запрос транслитерируется на лету, так
  что «Gödel» находится по «Гёдель» и наоборот; ищет по названию,
  альтернативному названию и авторам.
- **Онлайн-чтение** — PDF рендерится прямо в браузере (pdf.js), EPUB —
  через epub.js. Файлы в DjVu автоматически конвертируются в PDF при
  загрузке (нужен установленный `ddjvu` из пакета djvulibre).
- **Аккаунты по приглашениям** — регистрация закрыта, доступ выдаётся
  админом через одноразовый код (`/admin` → «Приглашения»).
- **Обсуждение и пометки** — комментарии с ответами под читалкой; отдельно
  — стикеры прямо на странице книги (выбор формы, цвета, текст, публично
  или только для себя).
- **Двухстраничная читалка** — PDF по умолчанию открывается разворотом
  (две страницы рядом), с переключением на одну страницу, анимацией
  перелистывания (можно выключить) и постраничными пометками.
- **Групповое редактирование метаданных** — любой зарегистрированный
  участник может поправить название/автора/раздел/описание; все изменения
  попадают в историю правок под текстом.
- **Карта связей** (`/graph`) — интерактивный граф разделов и авторов с
  zoom/pan, перетаскиванием узлов и подсветкой связей по клику; пунктиром
  показаны смысловые связи, отмеченные вручную («Философия математики» —
  между «Философией» и «Математикой»).

## Стек

Next.js (App Router) + TypeScript, Tailwind CSS, SQLite через Drizzle ORM
(`better-sqlite3`), pdf.js/epub.js для чтения, d3-force для графа.

## Запуск

Требуется Node.js 18.18+ (проверено на 18.20) и, для конвертации DjVu,
установленный `djvulibre` (`brew install djvulibre` / `apt install
djvulibre-bin`).

```bash
npm install
cp .env.example .env.local
npm run db:push          # создаёт таблицы в data/app.db
npm run create-admin -- you@example.com "Ваше имя" пароль-минимум-8-символов
npm run dev
```

Сайт откроется на [http://localhost:3000](http://localhost:3000). Войдите
под только что созданным админом на `/login` — в `/admin` появятся вкладки
«Материалы», «Разделы» и «Приглашения». Дальше новых участников зовут
приглашениями, а не паролем администратора.

## Хранение данных

- База данных: `data/app.db` (SQLite, в git не попадает)
- Файлы книг: `public/uploads/` (в git не попадает — там могут быть
  материалы с авторским правом, публиковать их в открытом репозитории
  нельзя)
- Схема БД: `lib/db/schema.ts`; после её изменения выполните `npm run
  db:push`

## Первичный импорт из папки BOOKS

`scripts/seed.ts` — одноразовый скрипт, который читает
`scripts/catalog-data.ts` (курируемое соответствие «файл → раздел, автор,
название») и раскладывает книги по базе и `public/uploads`, конвертируя
DjVu в PDF по пути. На обычную работу сайта эти файлы не влияют — после
первого импорта всё управление идёт через `/admin`.

```bash
BOOKS_SOURCE_DIR=/путь/к/BOOKS npm run db:seed
```

Часть файлов исходно называлась малоинформативно (хэши, обрезанные
названия); там, где название или автор не подтверждены метаданными или
известной библиографией, документ помечен «уточняется» — стоит проверить и
поправить через редактирование карточки.

Не были перенесены (сознательно): личные черновики с чужим адресом почты
(`e1 draft*`), сохранённая веб-страница документации Qiskit (не файл книги),
личные конспекты китайского (`China/слова/*`) и точные дубликаты по
содержимому — они остались нетронутыми в исходной папке.

`npm run db:seed` полностью пересобирает каталог: удаляет вообще все
документы (в том числе загруженные вручную через `/admin` или через
`scripts/import-github-repo.ts`) и все файлы в `public/uploads/`, поэтому
после его запуска сторонние импорты нужно повторить.

## Импорт из стороннего GitHub-репозитория

`scripts/import-github-repo.ts` — аддитивный импорт публичного репозитория
с литературой (сейчас настроен на
`dimitarpg13/information_theory_and_statistical_mechanics`; файлы читает
через Git LFS media-эндпоинт GitHub). В отличие от `db:seed` он не трогает
существующий каталог, а добавляет новый верхнеуровневый раздел «Теория
информации и статистическая механика» с подразделами «Книги» и «Статьи»
(по подпапкам исходного репозитория). Название и год определяются
автоматически из имени файла, поэтому все материалы помечены «уточняется» —
это нормально, поправить можно через `/admin`.

```bash
npm run import:repo
```

Повторный запуск безопасен — уже загруженные файлы (по исходному пути в
репозитории) пропускаются.

## Что нужно для работы сайта (хостинг)

Сайт — обычное Next.js-приложение с файлом SQLite и папкой загрузок на
диске, поэтому ему нужен сервер с постоянным диском, а не serverless-платформа
(Vercel/Netlify не подойдут без переноса БД и файлов на внешние сервисы).

Минимально достаточно:

- **VPS** — 1 vCPU / 1–2 ГБ RAM с лихвой хватит для личной библиотеки на
  небольшой круг читателей (нагрузка минимальная). Варианты: Timeweb,
  Selectel, Hetzner, DigitalOcean — от ≈300–600 ₽/мес или €4–6/мес.
- **Диск** — с запасом под книги: сейчас библиотека (BOOKS + импортированный
  сборник по теории информации) занимает около 3–4 ГБ; закладывайте
  20–30 ГБ на диске под дальнейший рост коллекции.
- **Node.js 20+** на сервере (в разработке использовался 18 из-за
  локального окружения, но для продакшена лучше 20 LTS — новее, быстрее,
  без предупреждений о несовместимости пакетов).
- **Домен** — свой (∼1000–1500 ₽/год для `.ru`/`.com`) либо бесплатный
  поддомен от хостинга на первое время.
- **HTTPS** — бесплатно через Let's Encrypt (Caddy/nginx с certbot).
- **Процесс-менеджер** — `pm2` или systemd-юнит, чтобы `next start`
  перезапускался при падении/перезагрузке сервера.
- **Резервные копии** — регулярно копировать `data/app.db` и
  `public/uploads/` (это единственные данные, которые нельзя
  восстановить); простой cron с `rsync`/`tar` на другой диск или в облако
  хранения будет достаточно.

Итого: один недорогой VPS (~€5/мес) с доменом и Node 20 закрывает все
требования — отдельная БД-хостинга или объектное хранилище не нужны, пока
коллекция не вырастет до десятков тысяч файлов.
