# Следующие этапы — план на согласование

> Исторический план аудита 16–17 октября. Владелец согласовал развитие; реализация и результаты проверок на 21 октября находятся в [implementation-progress.md](./implementation-progress.md). Указанные ниже ограничения прежней итерации не отменяют это разрешение.

Текущий проход ограничен диагностикой и локальной стабилизацией. Ниже — предложения, **не реализованные функции**. Схема данных и крупный редизайн требуют согласования по прямому указанию владельца в п.27 задания.

## 1. Стабильная библиотека

В текущем проходе добавлены 24 автоматических теста и браузерные сценарии чтения/выделения/сохранения/перезагрузки, комментариев с network/HTTP отказами, экспорта и прав. Следующий шаг — регулярно запускать этот набор и добавить реальные проблемные книги владельца: их отсутствие среди локальных fixtures не доказывает отсутствия ошибки. Поймать периодический верхний отступ с маршрутом, браузером, шириной, состоянием подписки/maintenance и переходами назад/вперёд; не добавлять отрицательный margin.

Следующий обязательный эксплуатационный шаг — резервная копия через SQLite backup API и проверка восстановления в отдельную папку. Затем заменить неявные runtime ALTER/CREATE на последовательные проверяемые миграции, не удаляя колонки/данные. До этого не расширять модель ролей/anchors.

## 2. Каналы — расширять существующие таблицы и API

Сейчас есть channels, posts, comments, moderators, follows и media attachments. Сначала выровнять редактирование детальной страницы и ленты, revalidation после сохранения, подтверждение удаления, пустое/error/loading состояния, пагинацию. Затем согласовать роль owner/admin/editor и область редактирования editor (все публикации канала или только свои); серверная policy должна быть единой для POST/PATCH/DELETE/forward/attachments. Существующих moderators мигрировать аддитивно с сохранением прав; не создавать вторую систему каналов.

Для публикаций предложен версионированный массив блоков (text, heading, list, image, video, link, book, quote, annotated-fragment, repost). Существующий body остаётся читаемым fallback, backfill проверяется на копии. Книга/цитата хранит documentId, optional text-version/hash и anchor; вложения остаются в community_attachments. Репост проверяет доступ к оригиналу и не раскрывает private notes. Создание поста + bind attachments должно быть атомарным; retry требует отдельного idempotency key, а не эвристики одинакового текста.

Критерий приёмки: A создаёт канал, B получает/теряет право публикации, C получает серверный 403 при подмене ID; текст/изображение/книга/цитата сохраняются и повторно открываются после reload. Демо-данные — отдельная тестовая SQLite копия/fixtures с реальными local document IDs, не production seed.

## 3. Цитаты и аннотации

Существующая геометрия привязана к странице, поэтому изменение TXT pagination или EPUB layout требует новой модели anchors. Предложение: documentId + content_hash (версия) + EPUB CFI либо текстовый offset + exact quote + prefix/suffix, с legacy page/rect fallback. Порядок восстановления: совпадение версии/позиции → проверка quote → однозначный поиск quote+контекста → явное «фрагмент не найден», без случайного прыжка на похожий текст. Не переписывать старые anchors массово.

Сценарий: выделение → «Поделиться» → доступные каналы → комментарий → preview с названием/автором → публикация → переход точно к месту. Личные заметки остаются личными; публикация пометок требует явного выбора. Экспорт EPUB/TXT с встроенными пометками сейчас не обещать: текущий annotated export — PDF.

## 4. Дизайн существующих страниц

- `Header`: единая модель для шапки и уведомлений, измеренная высота вместо независимых sticky top:0, проверка dropdown/мобильного меню и safe-area. Уведомления не должны перекрывать навигацию.
- `DocumentWorkspace`: перенос панели кнопок на узких экранах, читаемая длина строки, доступные фокус/ошибка/черновик. Пометки и поиск не должны перехватывать обычное выделение.
- `ChannelFeed`/`ChannelPostBody`: колонка чтения порядка 65–75ch, заметная дата/автор, отдельное оформление цитаты с источником и обложки/книги, список действий рядом с конкретным постом. Для media — ограниченная высота, сохранение пропорций, отображение pending/error. Длинные слова/URL переносятся.
- `/channels`: поиск и список каналов с числом публикаций/подпиской; оформление опирается на существующие paper/ink/rust tokens, без дополнительной библиотеки компонентов.
- Главная/каталог: сохранить журнальную типографику и направление нового дизайна; на ноутбуке проверить полезность первого экрана с крупным hero. Изменение масштаба hero — дизайнерское решение, не «исправление отступа».
- Общие controls: клавиатурный фокус, контраст, aria-live для ошибок, prefers-reduced-motion, длинные русские/греческие названия. Сначала системные состояния, затем декоративные переходы.

## 5. Форум и комнаты чтения

Форум уже существует: развивать forum_topics/posts/watches/reactions, а не создавать новую подсистему. Добавить понятное цитирование, ссылки к источнику, плоскую ветку с переходом к родителю на мобильном, пагинацию, модерацию/уведомления. Личные библиотеки/рейтинги/закладки также уже есть — завершать их интеграцию.

Семинары уже связаны с книгой/ведущим/темой обсуждения. Минимальная комната — доступ/участники + общий текст + лента указаний ведущего, opt-in следование позиции, сохранённые публичные для комнаты заметки. Первая версия использует существующую внешнюю ссылку на встречу и polling/SSE после оценки нагрузки; собственного WebRTC не нужно. Доступ по билетам/приглашениям должен распространяться на сообщения и вложения комнаты, а не только meetUrl.

## 6. Аналитика, ambient и дополнительные функции

**Аналитика:** расширять activity_events/admin-activity, различать account/session/page view и started/continued reading, ошибки импорта/API, p95 времени открытия. Не писать тексты личных заметок/сообщений в события. Согласовать retention и псевдонимизацию; сейчас audit не меняет сбор персональных данных.

**Ambient:** существующие reading-music/ambient-engine сначала оценить на устройстве. Сравнить: Web Audio synthesis (малые assets, риск неприятного синтетического звука); готовые loops (лучше звук, нужен бюджет загрузки и лицензии); несколько записанных слоёв с редкими вариациями (предпочтительный изолированный prototype после прослушивания). Start только жестом пользователя, fade in/out, CPU/battery/background ограничения на мобильном, reduced motion для винила. Прототип не внедрять в основной интерфейс без оценки качества/лицензии.

**Дополнительные функции, по возрастанию сложности:** подборки цитат/экспорт личных annotations (высокая польза, средняя сложность); поиск по названиям/авторам → публикациям/форуму → полнотекстовый индекс книг (отдельная pipeline extraction/versioning); смысловые связи цитат/понятий (после anchors); семинарские подборки и сопоставление переводов (после works/editions и устойчивых ссылок). Не реализовывать всё одновременно.

Отдельно — редактор content blocks и существенный редизайн ленты. Нужны решение о пределах редакторских прав, приватности комнат, допустимом формате аннотированного экспорта и приоритет между цитатами/каналами и комнатами.
