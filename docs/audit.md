## Повторение проверок

Из корня проекта, с установленными текущими зависимостями:

```sh
npm test
node node_modules/typescript/bin/tsc --noEmit --incremental false
npm run lint -- --quiet
node tests/support/prepare-browser.cjs
```

Последняя команда через SQLite backup API читает `data/app.db` (либо `BLABLA_SOURCE_DB`) и создаёт временную копию, тестовых пользователей и `fixtures.json`; исходную БД не меняет. Выводит пути к **копии** БД и fixtures. При необходимости выбрать книги через `BLABLA_TXT_ID`, `BLABLA_EPUB_ID`, `BLABLA_PDF_ID`.

Запустить отдельный сервер, подставив выведенный путь:

```sh
DATABASE_PATH="/путь/из/вывода/test.db" NEXT_DIST_DIR=.next-regression npm run dev -- --hostname 127.0.0.1 --port 3100
```

В другом терминале задать `BLABLA_TEST_FIXTURES` с выведенным путём `fixtures.json`, `PLAYWRIGHT_MODULE` с путём к уже установленному модулю Playwright и при необходимости `PLAYWRIGHT_CHROMIUM_EXECUTABLE` с путём к Chrome. Затем:

```sh
node tests/reader-browser.cjs
node tests/workflows-browser.cjs
```

Playwright не добавлен в зависимости проекта. Скрипты разрешают только `127.0.0.1` и создают тестовые записи: сервер должен работать именно с созданной копией БД. Для сборки также задавать `DATABASE_PATH` копии и отдельный `NEXT_DIST_DIR`: импорт `lib/db/client.ts` запускает существующие runtime ALTER/CREATE. Next может добавить include для нового dist в tsconfig; после остановки тестового сервера убрать только эти добавления и собственный временный dist.

Следующий этап — подтвердить воспроизведение верхнего отступа/проблемных книг, затем согласовать ограниченный пакет из [roadmap.md](roadmap.md). Масштабная переработка не начата согласно п.27 задания.
